# Map data research: sources, terms, licensing and cost

Research date: 2026-11-18. Scope: where Maploom gets geocoding, vector features, POIs and
picker tiles, what the terms allow for a product that **sells printed artwork**, and what it costs.

**This document is not legal advice.** It summarises public terms as an engineer read them.
Before selling physical products, have a lawyer review the ODbL attribution/share-alike
position, the AI-image terms and the print-provider agreements.

## 0. How to read this document (verification status)

The research session could not open pages directly: every direct fetch (osmfoundation.org,
mapbox.com, developers.google.com, openfreemap.org, photon.komoot.io, overpass-api.de,
wiki.openstreetmap.org) was blocked by the sandbox network policy. All facts below therefore
come from **web-search result extracts**, not from reading the full page. Each claim is tagged:

- **[O]** extract quoted from the provider's own page (official source, but only a snippet was seen)
- **[S]** secondary source only (blog, aggregator, forum, vendor comparison) - re-check before relying on it
- **[U]** unverified in this session: background knowledge of the author, or sources conflict

Every price and limit must be re-confirmed on the linked official page before it goes into a
budget or a contract decision. Items that most need a human re-check are listed in section 11.

## 1. Summary of findings

1. The preliminary architecture (OSM as truth, swappable geocoder, own SVG renderer, MapLibre
   only for the picker) **holds up**. Mapbox and Google are both contractually unsuitable as the
   data source for printed artwork, so there is no realistic proprietary alternative to OSM-based
   data for this product.
2. **Public Nominatim cannot be used for autocomplete** (policy forbids it) and is capped at
   1 request/second per application. It is usable only for the final "resolve this address"
   call at low volume. [O]
3. **Public Photon and public Overpass are dev-only dependencies**, not launch dependencies.
   Photon's terms are "be fair, extensive usage will be throttled, no availability guarantee" [S];
   Overpass's main instance defends itself against overuse, had a period in 2025 of blocking
   AWS/Azure address ranges, and community reports of IP blocks continue in 2026 [O/S].
   A server-side production path through these is fragile. This is the main correction to the
   preliminary plan: **the "paid or self-hosted" step must happen before paying customers, not
   "at scale".**
4. OSM attribution is required **on the physical product** where possible, on packaging and at
   the point of sale, with the URL `openstreetmap.org/copyright` printed out. [O] The artwork
   template needs a reserved attribution line from day one.
5. The printed/SVG artwork is an ODbL **Produced Work** (attribution only, no share-alike on the
   image). Share-alike risk sits in the *database* we keep: if we alter OSM-derived data and
   publicly use works made from it, ODbL 4.6 requires offering the altered database or the
   alterations. Keep OSM data unmodified and keep personalisation / other datasets in separate
   tables. [O for Produced Work; U for the 4.6 reading]
6. Overture Places (CDLA-Permissive-2.0 / Apache-2.0, no share-alike) is a usable POI supplement,
   but it has **no popularity signal**; `confidence` is an existence estimate, not prominence. [O/S]
   The best open prominence signals are OSM `wikidata`/`wikipedia` tags plus Wikipedia-derived
   importance scores.
7. Geodata cost on the open stack is roughly $0 at 10-100 maps/month, $20-100 at 1,000 and
   $100-300 at 10,000. Geodata is not a meaningful cost driver compared with printing.

## 2. OpenStreetMap ecosystem

### 2.1 Nominatim (public instance, nominatim.openstreetmap.org)

Policy: https://operations.osmfoundation.org/policies/nominatim/

- Absolute maximum **1 request per second**, counted per application/website (all users of the
  app combined), not per end user. [O via search extract; widely repeated]
- **Auto-complete is not allowed**: "Auto-complete search - This is not yet supported by
  Nominatim and you must not implement such a service on the client side using the API."
  [S: quoted in a forum post citing the policy; consistent with OSM-dev list threads]
- Must send an identifying `User-Agent` or `Referer`; put a caching proxy in front where
  possible; show OSM attribution. [O/S]
- Bulk geocoding discouraged; "periodic requests from apps are considered bulk geocoding". [O]
- No SLA; the policy "may change without notice"; access can be withdrawn. [O]
- The policy has an LLM clause: code generated by LLMs must adhere to the policy. [O] (Relevant
  because parts of this codebase are AI-written.)

Self-hosting: https://nominatim.org/release-docs/latest/admin/Installation/
- Full planet: at least 1 TB disk, NVMe recommended; import about 2.5 days on a well configured
  machine, 4-5 days on ordinary SSDs. Docs give tuning values for a 128 GB RAM machine; older
  docs said 64 GB+ strongly recommended. [O]
- Country/region imports are far smaller and are the sensible first self-hosted step. [U]

Verdict: fine as the **final forward/reverse geocode provider at low volume**, with caching.
Not an autocomplete provider.

### 2.2 Photon (komoot public instance, photon.komoot.io)

- Search-as-you-type geocoder built on OSM/Nominatim data; Apache-2.0 software. [U]
- Public instance terms, as quoted by a third-party package: you can use the API for your
  project, please be fair, extensive usage will be throttled, availability is not guaranteed
  and usage may change. A client library defaults to 1 request/second against it. [S]
- No statement was found that explicitly permits or forbids commercial use. [S] Treat as
  "tolerated, no guarantee".
- Project README: for larger request volumes, set up a private instance. [O]

Self-hosting: https://github.com/komoot/photon
- Requires Java 21+. Pre-built dumps (planet and per-country) are published weekly; dump version
  must match the Photon version. [O/S]
- Planet index about 95 GB on SSD/NVMe according to one listing; another guide says up to
  ~600 GB (probably a different configuration). RAM requirement not confirmed. [S, conflicting]
- Country extracts exist and are small enough for a modest VPS. [O: nominatim.org blog]

Verdict: best open autocomplete engine. Use the public instance for development and demos
only; self-host (country extracts first) or buy a hosted OSM-based autocomplete before launch.

### 2.3 Overpass API

Docs: https://dev.overpass-api.de/overpass-doc/en/preface/commons.html ,
https://wiki.openstreetmap.org/wiki/Overpass_API

- Main instance (overpass-api.de) guideline: about **10,000 requests/day and under ~1 GB
  download/day** is within safety margins. [O via extract of the Commons page]
- The OSM wiki adds that for anything running *regularly* you should divide those numbers by
  100 (about 100 queries and 10 MB per day). [S: wiki extract]
- The instance rate-limits per IP with slots; HTTP 429 means back off (community practice:
  stop and wait at least 30 s). Send an identifying User-Agent. [S]
- In 2025 the main instance announced it would **block Azure and AWS ranges for some time**
  (thread: https://community.openstreetmap.org/t/overpass-api-will-block-azure-and-aws-for-some-time/136817),
  and there is a long "Overpass API performance issues" thread
  (https://community.openstreetmap.org/t/overpass-api-performance-issues/140598). 2026 threads
  still report IP blocks. [O: thread titles; S: details] A backend hosted on a major cloud may
  simply not be able to reach it.
- Other public instances: `overpass.private.coffee` and the VK Maps instance
  (`maps.mail.ru/osm/tools/overpass`) are reported as having no explicit rate limit [S, single
  non-authoritative source]; `overpass.kumi.systems` status not confirmed [U]. None offers an SLA.
- Self-hosting is the documented answer for heavier demand. A 2026 OSM diary series documents
  container-based regional setups (https://www.openstreetmap.org/user/SomeoneElse/diary/408252). [O/S]
  Planet-scale Overpass needs a large SSD (hundreds of GB) [U]; regional instances are modest.

Verdict: excellent for prototyping the feature schema. In production use it only behind a
cache keyed by (bbox tile, query version), with mirror failover, and plan to replace it with
PostGIS extracts. With 1-3 queries per created map, 1,000 maps/month is ~30-100 queries/day,
which already sits at the wiki's "regular use" ceiling.

### 2.4 Extracts and the planet

- **Geofabrik** (https://download.geofabrik.de): free daily regional/country PBF extracts,
  offered free of charge by Geofabrik GmbH. [O] (An OSM login is needed only for the
  "internal" extracts that include user metadata. [U]) A forum report mentions download
  throttling of about 40 files then 1/hour; anecdotal. [S]
- **BBBike extracts** (https://extract.bbbike.org): custom rectangles/polygons, up to
  24,000,000 km2 or 512 MB per extract in the free service. [S: wiki extract] Useful for
  one-off city cut-outs, not for an automated pipeline.
- **Planet** (https://planet.openstreetmap.org): weekly PBF, "tens of GB"; 62.4 GB in 2022,
  "70+ GB" in a later guide. [S] Expect roughly 80-90 GB in 2026. [U]
- OSMF "Regional Cuts" guideline: a geographic cut of OSM is still just OSM data under ODbL. [O]

### 2.5 osm2pgsql and imposm

- **osm2pgsql** (https://osm2pgsql.org): actively maintained; the "flex" output lets us define
  exactly the tables our renderer needs (roads, buildings, water, landuse, POIs) in Lua and
  supports diff updates. Recommended importer. [U - release status not re-verified this session]
- **imposm3** (https://github.com/omniscale/imposm3): fast, mapping-file driven, used by
  OpenMapTiles; development has been slow in recent years. [U] No reason to prefer it here.
- **Planetiler / tilemaker** build vector tiles (PMTiles/MBTiles) straight from PBF and are the
  tools behind OpenFreeMap-style and Shortbread/VersaTiles tile sets. [S/U] Relevant only if we
  self-host picker tiles.

### 2.6 Overture Maps

Docs: https://docs.overturemaps.org/attribution , https://docs.overturemaps.org/guides/places

Licences per theme:

| Theme | Licence | Notes |
|---|---|---|
| Places | CDLA-Permissive-2.0 and Apache-2.0 (per source) | "Contains no OpenStreetMap data and carries none of the share-alike obligations of the ODbL." [O] |
| Buildings | ODbL | Includes OSM plus ML footprints [O: 2024 release notes; S: 2026 mirror] |
| Transportation | ODbL | OSM-derived [O/S] |
| Base (land, water, land use, infrastructure) | ODbL | OSM-derived [O/S] |
| Divisions (admin boundaries, localities, neighbourhoods) | ODbL | [O for "Admins" 2024; U that this is unchanged in 2026] |
| Addresses | Permissive open licences per source, some with attribution terms | Per-source breakdown not seen [O] |

- Monthly releases as GeoParquet on public cloud storage (https://registry.opendata.aws/overture/),
  queryable by bbox with DuckDB without running a server. [O for registry; U for details]
- Places sources in the October 2026 release: Meta ~60.3M, Microsoft ~5.9M, Foursquare ~3.76M
  records. [S: table reported by a third party citing Overture docs]
- `confidence` (0-1) is an estimate that the place **exists**; 0 means permanently closed. [O]
  It is "Overture's source score, not audited accuracy". [S] An early community audit in
  Salvador, Brazil found accuracy 81% at >=0.6 and 95% at >=0.9, with misplaced and outdated
  places as the main defects; early Meta rows carried a fixed 0.6. [S, 2023 - old]
- The schema changed in September 2026: `categories` replaced by `basic_category` and
  `taxonomy`. [O] Pin a release and write a schema adapter.
- **No popularity signal**: no ratings, reviews, visit counts or popularity fields in the base
  schema. [S] Overture is useful for *recall* (finding businesses OSM lacks) and for brand /
  category fields, not for ranking.

Verdict: optional secondary POI source, filtered at confidence >= ~0.8-0.9 and de-duplicated
against OSM by distance + name. Buildings/transport from Overture bring no licensing advantage
over OSM (still ODbL) but the GeoParquet format is a convenient serverless fallback.

### 2.7 Importance / popularity signals from open data

- OSM has no general "importance" tag. [S]
- `wikidata=*` / `wikipedia=*` tags are the best prominence hint: Nominatim computes its
  `importance` score from Wikipedia page-rank/page-view derived values and publishes a
  Wikimedia-based scoring file covering ~17 million titles
  (https://nominatim.org/2024/08/07/wikimedia-file.html). [O]
- Nominatim/Photon responses expose `importance`; our POI ranker can reuse it at no cost. [U]
- QRank (Wikidata pageview ranking, CC0) is a commonly used alternative; not verified this
  session. [U]
- Heuristics available in raw OSM: feature class (`tourism=attraction`, `historic=*`,
  `leisure=park`), polygon area, tag richness (`website`, `opening_hours`, `brand:wikidata`),
  `heritage=*`, proximity to the user's address. [U]
- Wikidata content is CC0; Wikipedia text is CC BY-SA (do not print article text). [U]

## 3. Mapbox

Pricing: https://www.mapbox.com/pricing . Terms: https://www.mapbox.com/legal/tos and Product
Terms PDFs. All prices below are **[S]** (aggregators quoting the pricing page) unless marked.

| Product | Free tier / month | Price after |
|---|---|---|
| Map Loads for Web (GL JS) | 50,000 | $5.00 /1k to 100k, $4.00 /1k to 200k |
| Temporary Geocoding API | 100,000 requests | $0.75 /1k, then $0.60, $0.45 |
| Permanent Geocoding API | none | $5.00 /1k |
| Search Box API (sessions: suggest + retrieve) | 2,500 standard, or 500 under "preview pricing" (sources conflict) | $11.50 /1k standard; $3.00 /1k preview |
| Static Images API | 50,000 | $1.00 /1k, then $0.80, $0.60 |

Terms that matter:

- **Temporary vs permanent geocoding**: Product Terms (Oct 2025 version): the customer "shall
  not export, store, or cache Temporary Geocodes"; Permanent Geocodes may be stored
  permanently. [O: PDF extract] An order record that keeps the customer's coordinates therefore
  needs the Permanent endpoint.
- **Print**: Product Terms (2026 versions): "all print rights are limited to Mapbox Streets v8
  or later excluding Japan map data"; printed media means **printed paper copies and static
  digital copies (PDF, JPG, PNG)**; additional print or video rights can be purchased. [O: PDF
  extract] Mapbox docs: to print images from the Studio print export "for any use, contact us";
  Studio includes 100 high-resolution exports per account; Static Images API is capped at
  1280x1280 px and does not produce SVG/EPS/PDF; printed maps need Mapbox + OSM attribution and
  the logo. [O: docs extracts]
- **Tracing / deriving**: tracing is allowed only from satellite imagery for non-commercial use
  or for OpenStreetMap; otherwise "may not trace Mapbox maps or otherwise derive or extract
  data from them". [O: Product Terms / Atlas licence extracts]
- Licence is non-exclusive, non-transferable, non-sublicensable, revocable. [O]
- Mapbox GL JS v2+ is proprietary and requires a Mapbox token; MapLibre GL JS is the open fork
  of v1. [U]

Verdict: **unsuitable as the artwork data source.** Play mats, rugs and canvas are not "printed
paper copies"; extracting vector features to redraw them is "deriving data"; resale as a
product needs a negotiated print licence. Mapbox could technically serve the picker and
autocomplete, but it adds lock-in and a token for no benefit over MapLibre + an OSM geocoder.

## 4. MapLibre and tile sources (picker only)

### 4.1 MapLibre

- **MapLibre GL JS**: BSD-3-Clause, WebGL vector-tile renderer, style-spec JSON, no token, any
  tile source (https://maplibre.org). [U] **MapLibre Native**: BSD-2-Clause, iOS/Android/desktop
  and headless server-side rendering. [U]
- Custom styles: standard MapLibre style JSON; schema depends on the tile source (OpenMapTiles
  schema for OpenFreeMap/MapTiler; Shortbread for VersaTiles and OSMF vector tiles; Protomaps
  basemap schema for Protomaps). A style is tied to a schema, so switching tile providers
  across schemas means swapping the picker style. Keep the picker style thin.
- Self-hosting: a single PMTiles file on object storage + CDN, or `planetiler`/`tilemaker`
  output behind nginx. No tile server process is required with PMTiles. [O: Protomaps docs]

https://cloud.google.com/maps-platform/terms/maps-service-terms):

- **No caching** of Google Maps Content except as expressly permitted (ToS 3.2.3(a)/(b)).
  Lat/lng from Geocoding/Places may be cached for at most **30 consecutive days**; Place IDs may

Verdict: **unsuitable.** A Google geocode may not be shown on our (non-Google) picker, may not
be kept with the order beyond 30 days, and nothing derived from Google content may become
artwork. Google is also the most expensive option at volume (section 9).

## 7. Comparison and recommendation per need

| Need | Dev / up to ~100 maps per month | Launch default | Scale-up | Avoid |
|---|---|---|---|---|
| **Autocomplete geocoding** | Public Photon (debounced, proxied, cached) | Hosted OSM-based autocomplete with storage rights (Geoapify, LocationIQ or Stadia Starter) *or* self-hosted Photon with country extracts | Self-hosted Photon (planet) | Public Nominatim (forbidden); Google/Mapbox (storage + non-Google-map limits) |
| **Forward geocode of the chosen result** | Use the coordinates already returned by the autocomplete hit; public Nominatim as fallback (<= 1 req/s, cached) | Same provider as autocomplete | Self-hosted Nominatim or Photon | Temporary-only geocoders |
| **Reverse geocoding** (pin dropped on picker) | Public Nominatim `/reverse` or Photon `/reverse` | Same paid provider | Self-hosted; or a point-in-polygon lookup against our own PostGIS admin/neighbourhood tables | - |
| **Vector features** (roads, buildings, water, parks, landuse) | Public Overpass with cache + mirror failover | Self-hosted Overpass or PostGIS loaded from Geofabrik extracts for launch countries | PostGIS (osm2pgsql flex) with daily diffs; Overture GeoParquet as serverless fallback | Vector tiles as artwork source (generalised geometry, schema/licence coupling); Mapbox/Google |
| **POIs + popularity** | OSM POIs from the same Overpass query; rank by `wikidata`/`wikipedia` presence + class heuristics | Add Wikipedia-derived importance; optional Overture Places (confidence >= 0.8-0.9) kept in separate tables | Add FSQ OS Places if recall is insufficient | Google Places, Foursquare commercial API (cost, storage terms) |
| **Interactive basemap tiles** (picker) | OpenFreeMap | OpenFreeMap + PMTiles fallback on our bucket | Self-hosted PMTiles behind CDN | MapTiler/Stadia free plans (non-commercial); Mapbox GL JS |

## 8. Legal and licensing

Not legal advice. Items here should be reviewed by counsel before the first physical sale.

### 8.1 ODbL: Produced Work vs Derivative Database

- OSM data is under ODbL 1.0 (https://www.openstreetmap.org/copyright).
- OSMF Produced Work guideline (endorsed 2014-06-06,
  https://osmfoundation.org/wiki/Licence/Community_Guidelines/Produced_Work_-_Guideline): "If
  the published result of your project is intended for the extraction of the original data, then
  it is a database and not a Produced Work. Otherwise it is a Produced Work." Examples given:
  PNG, JPG, PDF, **SVG** images, and "a map in a physically printed work". [O]
  => Our SVG artwork, print PDFs and the printed mat/poster/canvas are Produced Works. They
  need **attribution**, but the image itself is not under share-alike and we may license the
  artwork however we like.
- Caveat from the same guideline: if a Produced Work is used to extract or recreate substantial
  parts of the data, the result is a Derivative Database. [O] Do not publish an API or bulk
  download of machine-readable SVG layers that amounts to redistributing OSM geometry at scale;
  individual customer downloads of their own artwork are fine in spirit.
- ODbL 4.6 (author's reading of the licence text, not re-fetched [U]): if we publicly use a
  Produced Work made from a **Derivative Database**, we must on request offer either that
  database or a file of the alterations / the method of making them. Internal caching, format
  conversion and filtering are generally treated as non-substantive (see the "Trivial
  Transformations" guideline [U]); *editing* OSM data (fixing names, moving geometry, merging in
  other data feature-by-feature) creates alterations we could be asked to disclose.
  Practical rule: **never mutate OSM-derived rows**. Store corrections, user personalisation
  ("Grandma's house"), style choices and third-party data in separate tables keyed by OSM id.
- Collective Database guideline (endorsed 2016-06-17): using an ODbL database alongside another
  database can form a Collective Database rather than a Derivative one, under stated
  conditions. [O for existence; conditions not read] Keeping Overture Places (CDLA) and OSM in
  separate tables, joined at render time rather than conflated into one table, is the
  conservative design.
- Geocoding guideline (endorsed 2017-08-24): individual geocoding results are insubstantial
  extracts; storing them does not trigger share-alike unless results are systematically
  collected into a database that reproduces a substantial part of OSM. Attribution still
  applies. [O] Storing each order's coordinates and label is fine.
- Caching OSM extracts privately creates no publication duty; ODbL obligations attach to public
  use/conveyance. [U]

### 8.2 OSM attribution on screen and on printed products

Guideline (adopted by the OSMF board 2021-06-25):
https://osmfoundation.org/wiki/Licence/Attribution_Guidelines

- Required credit is to "OpenStreetMap" (customary text "(c) OpenStreetMap contributors"), with
  a way to reach the licence information. On screen: a visible credit on or next to the map,
  linking to `https://www.openstreetmap.org/copyright`. MapLibre adds it automatically from the
  tile source. [O]
- Print: the credit goes beside the map or where other credits appear; "the URL to
  openstreetmap.org/copyright must be printed out". [O]
- **Physical merchandise with an aesthetic component**: attribution "on any packaging, at the
  point of sale, and, to the extent possible, somewhere on the item itself", readable, with the
  URL printed out; the text may sit near the image or on the item's label or tag. [O]
- A draft document mentions a 10 mm minimum for clothing; it is not the adopted text. [S]
  The FAQ's old "fewer than 100 features / under 10,000 m2" exemption should not be relied on. [S]
- OSMF trademark policy: do not put the OSM logo or name on products as branding without a
  licence; a plain attribution line is not trademark use. [O]

Recommended implementation:

1. On the artwork, in the bottom margin, small but legible at print size (>= 6 pt on posters,
   larger on rugs where fibre resolution is coarse):
   `Map data (c) OpenStreetMap contributors - openstreetmap.org/copyright`
2. Where the print method cannot hold small text (tufted rug): put the same line on the sewn
   label, hang tag or backing, **and** on the packing insert.
3. Product page and checkout (point of sale): same credit with a live link.
4. Web app: attribution control on the picker and under every rendered preview.
5. If Overture, WOF or FSQ data is used, add their credit lines on the web "Data sources" page
   and, where their licence requires it, alongside the OSM line.

### 8.3 Service usage policies (summary)

- Nominatim public: 1 req/s per app, no autocomplete, identify the app, cache, attribute, no
  bulk. Overpass public: ~10k requests / 1 GB per day ceiling, much less for regular automated
  use, back off on 429, no SLA, cloud ranges may be blocked. Photon public: fair use, throttled,
  no guarantee. OSMF vector tiles: no bulk download. (Sections 2 and 4.)

### 8.4 Mapbox and Google

- Mapbox: temporary geocodes may not be stored; print rights limited to Streets v8+, paper and
  static digital copies; no tracing/deriving data; extra print rights are a paid negotiation.
  (Section 3.)
- Google: no caching beyond 30 days for lat/lng, no use with non-Google maps, no content
  derived from Google Maps Content. (Section 5.)
- Neither may be used as a reference to trace or "correct" our artwork, including feeding their
  screenshots to an AI image model.

### 8.5 Overture, Foursquare, Who's On First

- Overture: Places CDLA-Permissive-2.0 / Apache-2.0; Buildings, Transportation, Base, Divisions
  ODbL; Addresses permissive per source. Attribution strings are listed on
  https://docs.overturemaps.org/attribution. ODbL themes carry the same obligations as OSM.
- FSQ OS Places: Apache-2.0 with attribution. WOF: per-source, attribution-based.

### 8.6 Fonts

- SIL Open Font License fonts (most Google Fonts) may be used in commercial print products.
  Per the OFL FAQ (https://openfontlicense.org/ofl-faq/): documents and artwork made with the
  font are not covered by the OFL, embedding does not change the document's licence, no credit
  is required in the printed piece, and the font just cannot be sold by itself. [O/S: FAQ
  mirrors, several versions]
- Converting text to outlines in the print SVG/PDF is fine. If we serve font files to browsers
  or bundle them in downloads, ship the OFL licence text with them. Reserved Font Names matter
  only if we modify a font. [U]
- Check each font individually: some Google Fonts are Apache-2.0 or UFL, and commercial
  foundry fonts need a licence that covers products for resale. [U]

### 8.7 Icons

- We draw our own icons (preferred; no third-party terms).
- Maki (Mapbox): CC0-1.0. Temaki: CC0-1.0. Both usable in commercial print without
  attribution. [O/S: repo metadata and icon registries]
- OpenStreetMap Carto: style and icon files are CC0-1.0 according to the OSM wiki; confirm
  against `LICENSE.txt` in the repository, since a few symbols have separate origins. [S]
- Osmic: icons CC0, the icon *font* under OFL. [S]
- Do not copy icons from Google Material "Maps" pins, Mapbox Streets sprites or Apple Maps.

Cross-cutting points:
- Contractual "ownership" does not create copyright. Purely AI-generated images may not be
  copyrightable (US Copyright Office position), so our artwork may have thin protection against
  copying; human-authored layout, selection and vector drawing strengthen it. [S/U]
- Infringement risk stays with us: prompts or reference images containing brand logos,
  characters or recognisable copyrighted buildings/sculptures can produce infringing output.
- Do not send Google/Mapbox map imagery to an image model as a reference (their terms forbid
  derived content). OSM-derived renders are fine as references.

### 8.9 Print-provider content policies

- Printful (https://www.printful.com/policies/download/intellectual-property-policy): only
  content you own or have the right to use; an Intellectual Property Policy replaced the older
  Acceptable Content Guidelines; avoid protected elements "including in AI-generated content". [O]
- Printify (https://printify.com/policies/updates/): update of 2026-07-08 makes the merchant
  responsible for **content supplied by their customers through personalisation fields**, as if
  the merchant had provided it. [O] Directly relevant: user-entered labels must be moderated.
- Gelato (https://support.gelato.com/en/articles/8996134): prohibits unlicensed logos, brand
  names, character likenesses and copyrighted artwork; the user warrants rights and indemnifies
  Gelato; Gelato may reject orders. [O]

Consequences for Maploom: all providers push IP liability to us. Risk areas are (a) POI labels
that are trademarks (store names as plain text labels are normally descriptive use; never
render brand **logos**), (b) user-entered custom text and uploads, (c) AI-drawn landmarks.
Keep a per-order record of data sources and licences to answer provider or rights-holder
queries.

### Reading the numbers

Under 1,000 maps/month every option is close to free. At 10,000 the open stack and Mapbox are
both in the low hundreds of dollars and Google roughly 2-4x higher. Cost does not decide this;
**terms do**: only the OSM-based stack allows storing results, drawing on a non-vendor map and
selling derived artwork.

## 10. Does the evidence contradict the preliminary architecture?

| Preliminary decision | Verdict | Adjustment |
|---|---|---|
| OSM as geographic source of truth | Confirmed; effectively the only viable option for sold print artwork | Budget for attribution on product, packaging and point of sale |
| Public Nominatim + Photon for dev/low volume | Partly: Nominatim must never serve autocomplete; Photon public has no commercial assurance | Autocomplete = Photon only; proxy, debounce, cache; move to paid/self-hosted **before launch** |
| Overpass with aggressive caching | Works for dev; unreliable for production (blocks of cloud ranges, 429s, "regular use" guidance ~100 queries/day) | Bring the PostGIS / self-hosted Overpass step forward to launch for launch countries |
| MapLibre + OpenFreeMap for picker | Confirmed (commercial use allowed, no limits, no key, as-is) | Keep a PMTiles fallback; note MapTiler/Stadia free plans are non-commercial |
| Own SVG renderer | Confirmed, and legally important: Produced Work, no vendor print terms | Never mutate OSM rows; keep other data in separate tables |
| Avoid vendor lock-in | Confirmed | Geocoder interface must carry a per-provider storage/caching policy |
| Overture for popularity signals (question) | Contradicted: Overture has no popularity data | Use wikidata/wikipedia importance + heuristics; Overture only for POI recall |
