# Decision record

One shared log so research and implementation never disagree. Newest decisions may supersede
older ones; superseded entries are kept and marked.

| # | Decision | Why | Alternatives considered |
|---|---|---|---|
| D-001 | **TypeScript monorepo (npm workspaces)**: `packages/core`, `geo`, `render`, `server`; `apps/web`, `apps/worker`. Packages are consumed as TS source (no build step). | One language end to end lets the *same renderer* run in the browser preview and the server export. | Python geo stack (OSMnx/GeoPandas): strong tooling, but a second runtime and no shared renderer. |
| D-002 | **OpenStreetMap is the only source of geographic truth.** | Only open data whose licence clearly permits selling derived artwork (ODbL "Produced Work", attribution required). Mapbox and Google terms restrict print/derivative use. | Mapbox, Google, HERE — see `research/MAP_DATA.md`. |
| D-003 | **Features come from OpenMapTiles-schema vector tiles (OpenFreeMap), not Overpass.** | Public Overpass refused/reset connections from cloud IPs in testing; tiles are fast (≈100 ms/area warm), versioned (reproducible), cacheable and keyless. The source is an interface (`TileSource`), so self-hosted PMTiles drops in. | Overpass (richer tags such as `wikidata`, but unreliable and policy-limited); PostGIS from extracts (best at scale; roadmap). |
| D-004 | **Geocoding behind `GeocodeProvider`**: Photon for type-ahead, Nominatim as fallback. Public instances are dev-only. | Nominatim's policy forbids autocomplete; Photon allows it. Both are OSM-based so results may be stored. | Paid OSM geocoders (Geoapify, LocationIQ, Stadia) — the planned production swap. |
| D-005 | **Own deterministic SVG renderer**; MapLibre GL is used *only* for the interactive area picker. | Illustrated look, full control of print output, identical preview/export, no WebGL limits. | MapLibre Native / Mapnik styling (cartographic, not illustrative); headless-browser screenshots (size caps). |
| D-006 | **All text is converted to vector outlines** (opentype.js, SIL OFL fonts from `@fontsource`). | Fonts can never go missing at the printer; exact text metrics for label placement; resvg cannot load WOFF anyway. | `<text>` + font files on the server. |
| D-007 | **No SVG filters and no element-level `opacity`** in artwork; texture comes from seeded geometry. | Filters are orders of magnitude slower at print size; `opacity` makes resvg 2.6 abort the process when an element falls outside a strip. Enforced by a test. | Filter-based watercolour (preview only). |
| D-008 | **Print export = resvg rasterising horizontal strips into a streaming PNG encoder** (`packages/server/src/png.ts`). | 14400×21600 px in ~36 s under 1 GB; strips verified pixel-equivalent to a single pass. | sharp/libvips (extra native dependency; not needed once the encoder streams). |
| D-009 | **Database: Postgres; embedded PGlite in development/tests.** Hand-written parameterised SQL behind a tiny `Db` port. | Zero-setup `npm run dev`, one SQL dialect, real Postgres in production. | SQLite (second dialect); an ORM (not worth it for ~8 tables). |
| D-010 | **PostGIS: not yet.** | Today no geographic query touches the database — geometry lives in content-addressed snapshots. PostGIS becomes the right tool when we self-host OSM extracts (roadmap P3). | PostGIS now (operational cost without a query that needs it). |
| D-011 | **Jobs: Postgres-backed queue (`FOR UPDATE SKIP LOCKED`)**, in-process worker in dev, `apps/worker` for scale. No Redis yet. | One less service; the queue is one file to replace with pg-boss/BullMQ/SQS later. | Redis + BullMQ. |
| D-012 | **Working name "Maploom"** (temporary). | Original, descriptive, not derived from any competitor. Needs trademark/domain checks before launch. | MapStory, Little Neighborhoods. |
| D-013 | **Guest-first, save is explicit.** Designs live in the browser until Save; saved designs and place names are AES-256-GCM encrypted; identity is an anonymous httpOnly cookie. | Home addresses are sensitive; the product must be usable without an account. | Mandatory accounts. |
| D-014 | **Products, sizes, DPI, bleed and prices are configuration** (`packages/core/src/products.ts`); print and payment vendors are ports with mock implementations. | Nothing is hard-coded around rugs; vendors can be swapped. Prices are placeholders. | Hard-wiring Printful/Stripe before sampling. |
| D-015 | **AI is not used in the MVP.** Landmark choice is a transparent scoring function; icons are an original hand-drawn set. | Deterministic, explainable, zero marginal cost, no hallucinated geography. AI is planned only for presentation (see `research/RENDERING_AND_AI.md`). | LLM ranking; generated landmark art. |
| D-016 | **Map rotation is out of scope for now.** | Keeps labels upright and the geography pipeline simple; north-up matches user expectation. | Rotatable frames (roadmap). |
| D-017 | **Landmark artwork aspect = map area aspect**; the title is an overlay, and auto-landmarks avoid the title zone. | Changing title options never forces a re-fetch of geography. | Reserving a title band outside the map. |
| D-018 | **Static, browser-only demo for GitHub Pages** (`npm run build:demo`, `.github/workflows/pages.yml`). The same UI runs with a browser-side backend (`apps/web/components/studio/api.ts`): geocoding and tiles are fetched directly by the browser, geography is built client-side, designs are kept in localStorage, exports are SVG or canvas PNG. | A free, shareable link without running servers. Possible because `packages/geo` and `packages/render` are isomorphic. | Deploying the server app (Render/Fly/Railway) — still the plan for the real product. **Trade-offs, accepted for the demo only:** search text goes straight from the browser to public Photon/Nominatim (rule 6 "no addresses in URLs" cannot hold without our proxy — the demo banner and `/privacy` say so); no CSP headers on Pages; no print-resolution PNG, orders, admin or server saves. |
